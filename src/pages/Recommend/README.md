# 추천받기 (`/recommend?step=1|2|3&sel=동`)

조건 입력 → 자치구별 예산 확인 → 추천 행정동의 3단계 마법사입니다.

- 파일: `Recommend.jsx`(단계 관리·로딩·저장), `Step1Input.jsx`, `Step2Gu.jsx`, `Step3Dong.jsx`, `Recommend.css`
- 상태: 조건은 전역 `cond`(입력 즉시 저장), 단계는 URL `step`, 선택한 동은 URL `sel`. 로컬: `dir`(슬라이드 방향), `loading`, `view`(리스트/지도 — 2·3단계 공유)
- 계산: `guBudgets(capital, area)` → 구별 예산, `ALL_DONGS` 중 통과한 구의 예측 가능한 동 → 추천 대상

## 공통 요소

| 요소 | 내용 |
|---|---|
| 모바일 상단 바 | ‹ 이전(1단계에서는 비활성) · "조건으로 추천받기" · `n/3` |
| 단계 표시 (`.rec-steps`) | 막대 3개 + 라벨(조건 입력 / 자치구별 예산 확인 / 추천 행정동). 지난 단계만 눌러 돌아갈 수 있음. 모바일은 번호를 빼고 현재 단계가 아니면 "자치구별"을 생략 |
| 단계 전환 | 앞으로는 오른쪽에서, 뒤로는 왼쪽에서 슬라이드(.4s) + 맨 위로 스크롤 |
| 계산 중 모달 (`.rec-loading`) | 다음 단계로 갈 때 2.2초. 스피너 → 1.2초 뒤 ✓. 문구: "지원금을 계산하고 있어요..." → "받을 수 있는 지원금을 찾았어요!" / "딱 맞는 동네를 찾고 있어요..." → "나에게 맞는 동네를 골랐어요!". 진행 중 ‹ 이전을 누르면 취소 |
| 계산 실패 | 모달이 닫히고 하단 오류 토스트. 문구는 API 명세 1.1의 오류 코드별(`lib/errors.js`): `NETWORK_ERROR` "인터넷 연결을 확인해 주세요" + [다시 시도], `DB_UNAVAILABLE` "잠시 후 다시 시도해 주세요" + [다시 시도], 그 밖은 공통 문구. `VALIDATION_ERROR`는 1→2단계에서 `errors`의 `field`를 입력 칸에 매핑해 칸 아래에 서버 문구를 빨간 글씨로 표시(나이·자본금·면적·경력·업종·자격증), 그 칸을 고치면 사라짐. `DONG_NOT_FOUND`는 토스트 후 홈으로 이동, `REC_NOT_FOUND`는 토스트 없이 `ts-last`의 `rec_id`만 지움(`hooks/useApiError.js`). 토스트는 4초 뒤 사라지고 조건은 유지. API 연결 전까지는 오프라인이거나 주소에 `?fail=오류코드`(예: `db_unavailable`)를 붙였을 때만 발생 |
| 모바일 고정 CTA (`.rec-mob-cta`) | 1·2단계에서 탭바 바로 위. "지원금 계산하기" / "N개 구에서 동네 추천받기" |
| 탭바의 추천받기 | 다시 누르면 1단계로 |

## 1단계 · 조건 입력 (`Step1Input`)

| 요소 | 내용 |
|---|---|
| 나이 | 숫자만, 최대 3자리. 15~99 밖이면 빨간 테두리 + "15~99세만 가능해요", 다음 단계 차단. 나이를 줄이면 경력도 (나이 − 15)로 깎임 |
| 경력 | − / 숫자 입력 / +. 0 ~ (나이 − 15)년 |
| 자본금 | 만 원 단위, 천 단위 콤마. 아래에 한글 환산("1억 2,000만원"), 0이면 "만원 단위로 입력해 주세요" + 다음 단계 차단 |
| 희망 면적 | ㎡, 아래에 "약 n평". 비거나 0이면 빨간 테두리 + 다음 단계 차단 |
| 희망 업종 | 대분류 칩 3개(외식업·서비스업·소매업) → 세부 업종 칩. 대분류를 바꾸면 첫 세부 업종 선택 |
| 자격증 | 태그 입력. 검색어를 치면 추천 최대 4개 + "‘○○’ 직접 추가". Enter는 첫 추천(없으면 입력값) 추가, ×로 삭제(사라지는 애니메이션) |
| 입력한 조건 (데스크톱 사이드) | 나이·자본금·면적·경력·업종·자격증 수 요약 + 안내 문구 + [지원금 계산하기] |

입력 칸은 포커스 시 파란 테두리와 링이 생깁니다.

## 2단계 · 자치구별 예산 확인 (`Step2Gu`)

**용어**: 가용 예산 = 자본금 + 지원금. 추정 초기 임대비용 = 보증금(월세 15개월) + 월세 3개월 = 월세 × 18 (희망 면적 비례). 예산 여유 = 가용 예산 − 추정 초기 임대비용.

| 요소 | 내용 |
|---|---|
| 나이 안내 (`.s2-warn`) | 39세 초과면 노란 배너 |
| 요약 카드 | "25개 구 중 **N곳**에서 임대료를 감당할 수 있어요", 25칸 상태 띠(초록 통과 / 진회색 정보 없음 / 빨강 오류 / 연회색 탈락), 조건 칩 6개, 범례(자본금·지원금·임대비용), 계산식 |
| 리스트 ↔ 지도 토글 | |
| 이전 / N개 구에서 동네 추천받기 | 데스크톱만 (모바일은 고정 CTA) |

**리스트 보기** — 통과(여유 큰 순) → 임대료 정보 없음 → 오류 → 탈락 순.

| 요소 | 내용 |
|---|---|
| 행 | 구 이름, 가용 예산, 예산 여유(통과 초록 / 탈락 빨강 / 정보 없음이면 "통과" + 배지), ▾ |
| 예산 막대 | 자본금(파랑) + 지원금(초록) 누적, 검은 눈금 = 추정 초기 임대비용 |
| 탈락 | 반투명 + "탈락 · 추정 초기 임대비용이 가용 예산보다 N만 원 많아요" |
| 지원 사업 없음 (은평구) | "매칭된 지원 사업이 없어 자본금만으로 계산했어요" |
| 데이터 오류 (용산구) | 빨간 안내 상자 + [다시 시도](잠시 "불러오는 중…" 뒤 오류 토스트), 펼칠 수 없음 |
| 펼침 | 받을 수 있는 지원 사업(이름·금액), 중복 수혜로 제외(취소선 + 사유), 계산식과 임대비용 기준. 한 번에 한 구만 열림(처음엔 관악구) |

**지도 보기** — `GuVectorMap`.

| 요소 | 내용 |
|---|---|
| 구 색 | 예산 여유가 클수록 진한 초록, 탈락 회색, 정보 없음 빗금, 오류 연빨강. 선택한 구는 파란 외곽선 |
| 조작 | 구를 누르거나 Tab + Enter로 선택, 마우스를 올리면 툴팁 |
| 범례 | 지도 왼쪽 아래 |
| 선택한 구 카드 | 구 이름, 가용 예산, 상태(여유 / 탈락 / 정보 없음 / 오류), 예산 막대, 지원 사업, 설명 |

## 3단계 · 추천 행정동 (`Step3Dong`)

진입하면 결과를 `last`에 저장합니다(대시보드·상세·비교에서 사용).

| 요소 | 내용 |
|---|---|
| 제목 | ‹(데스크톱) · "추천 행정동 N곳" · "감당 가능한 N개 구 안에서 · 업종" |
| 리스트 ↔ 지도 토글 | |
| 정렬 칩 | 종합점수순 · 예산 여유순 · 생존 기간순 · 매출순 · 성장세순 (가로 스크롤) |

**리스트 · 데스크톱** — 왼쪽 목록 + 오른쪽 고정 상세 패널.

| 요소 | 내용 |
|---|---|
| 목록 행 | 순위, 이름·구·주거지역 배지, 생존/월매출 80% 범위, 예산 여유, 점수(구간별 색), ♡. 누르면 선택(파란 테두리) |
| 상세 패널 | 이름·구·업종, 종합점수(44px), ♡ / 예상 생존 기간·예상 월매출 범위 막대(하한·상한 라벨) / 성장세(+신뢰도 낮음), 예산 여유 / **왜 추천됐나요?**: 가중치, 요인 누적 막대, 요인별(매출·생존·성장세) 기여 점수·막대·원값·서울 상위 %, 성장세 데이터가 없으면 노란 안내 / [상세 분석 보기 ›] |

**리스트 · 모바일** — 카드. 헤더(순위·이름·점수·♡), 생존·매출 범위 막대, 예산 여유 줄, "왜 추천됐나요? ▾"를 누르면 요인별 점수와 [○○ 상세 보기 ›]가 펼쳐집니다.

**지도 보기** — `DongLeafletMap` + 순위 미니 목록(스크롤) + 선택한 동 요약 카드(범위 3칸, [상세 분석 보기 ›]). 핀이나 목록을 누르면 선택이 바뀌고 지도가 그 동으로 이동합니다.

점수 색: 80 이상 초록, 70 이상 파랑, 60 이상 주황, 그 아래 빨강.

## 반응형

| 폭 | 레이아웃 |
|---|---|
| 1040px 이상 | 사이드 패널 고정(sticky). 2단계는 요약이 오른쪽 |
| 900~1039px | 사이드 패널이 본문과 줄바꿈되며 위/아래로 |
| 900px 미만 | 한 열, 1단계 요약 패널 숨김, CTA는 탭바 위 고정, 3단계 리스트는 카드형 |

## 예외

- 추천할 동이 없으면(통과한 구에 예측 가능한 동이 없음) 3단계에 빈 상태와 [이전 단계로]를 보여 줍니다.
- `?step=3`으로 바로 들어와도 저장된 조건으로 계산합니다.
