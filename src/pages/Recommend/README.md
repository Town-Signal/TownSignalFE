# 추천받기 (`/recommend?step=1|2|3&sel=동`)

조건 입력 → 자치구별 예산 확인 → 추천 행정동의 3단계 마법사입니다.

- 파일: `Recommend.jsx`(단계 관리·로딩·저장), `Step1Input.jsx`, `Step2Gu.jsx`, `Step3Dong.jsx`, `RestoreSkeleton.jsx`(2 · 3단계 복원 중 스켈레톤), `Recommend.css`
- 불러오는 동안: 안내 문구 대신 실제 배치와 같은 회색 막대(스켈레톤, `ui.jsx`의 `Sk` · `SkKpi`) — 1단계 업종 칩, 2단계 공고 펼침, 2 · 3단계 복원(요약 띠 · 목록 · 패널), 지도 자리. 값이 오면 페이드로 들어온다. 데스크톱 위 여백 · 간격은 세 단계 모두 같다(16px · 20px, 단계 표시가 제자리)
- 상태: 조건은 전역 `cond`(입력 즉시 저장), 단계는 URL `step`, 선택한 동은 URL `sel`. 로컬: `dir`(슬라이드 방향), `loading`, `view`(리스트/지도 — 2·3단계 공유)
- API: ② 구별 예산 · ③ 공고 상세 · ④ 추천 · ⑤ 복원(`view.js`가 표시 모양으로 옮긴다). 지도는 geo_code로 잇는다
- 본문 폭: 대시보드처럼 최대 1440px(다른 화면은 1160px). 푸터도 같은 폭에 맞춘다

## 공통 요소

| 요소 | 내용 |
|---|---|
| 모바일 상단 바 | ‹ 이전(1단계에서는 비활성) · "조건으로 추천받기" · `n/3` |

| 단계 전환 | 앞으로는 오른쪽에서, 뒤로는 왼쪽에서 슬라이드(.4s) + 맨 위로 스크롤 |

| 탭바의 추천받기 | 다시 누르면 1단계로 |

## 1단계 · 조건 입력 (`Step1Input`)

카드 하나가 폭을 다 씁니다(입력값을 다시 보여 주는 요약 패널은 없음). 머리 아래 네 묶음(`.s1-grid`) **기본 정보 · 자격증 · 거주 구 · 희망 업종**이 있고, 계산 버튼은 카드 밖 하단 바에 있습니다.

| 폭 | 배치 |
|---|---|
| 1040px~ | 왼쪽 열 위 기본 정보(나이 · 경력 / 자본금 · 면적 2×2) · 아래 자격증 · 거주 구 \| 오른쪽 열 희망 업종(폭 1 : 1.8, 왼쪽 최소 380px, 사이는 구분선). 업종이 100개라 세부 업종 칩이 들어갈 오른쪽을 넓게(소매업 31개가 1440px 4줄 · 1040px 8줄, 양쪽 열 높이가 비슷) |
| 900~1039px | 위아래로 쌓고 사이에 가로 구분선(기본 정보는 한 줄, 자리가 모자라면 줄바꿈) |
| ~899px(모바일) | 위아래로 쌓고, 기본 정보는 PC처럼 2×2(나이 · 경력 / 자본금 · 면적). 칸이 좁아(360px 화면 137px) 자본금 숫자도 다른 칸과 같은 17px |

| 요소 | 내용 |
|---|---|
| 나이 | 숫자만, 최대 3자리. 15~99 밖이면 빨간 테두리 + "15~99세만 가능해요", 다음 단계 차단. 나이를 줄이면 경력도 (나이 − 15)로 깎임 |
| 경력 | − / 숫자 입력 / +. 0 ~ (나이 − 15)년 |
| 자본금 | 만 원 단위, 천 단위 콤마. 아래에 한글 환산("1억 2,000만원"), 0이면 "만원 단위로 입력해 주세요" + 다음 단계 차단 |
| 희망 면적 | ㎡, 아래에 "약 n평". 비거나 0이면 빨간 테두리 + 다음 단계 차단 |
| 희망 업종 | 대분류 칩 3개(외식업·서비스업·소매업) → 세부 업종 칩. 대분류를 바꾸면 첫 세부 업종 선택. 아직 고르지 않았으면 제목 옆에 주황 "선택 필요" 배지 |
| 자격증 | 제목 옆 "선택" 배지 + "일부 지원사업 조건에 쓰여요" 안내 — 비워도 계산된다. 태그 입력. 검색어를 치면 추천 최대 4개 + "‘○○’ 직접 추가". Enter는 첫 추천(없으면 입력값) 추가, ×로 삭제(사라지는 애니메이션) |
| 거주 구 | 제목 옆 "선택" 배지 + "일부 구청 지원사업은 그 구에 사는 청년만 신청할 수 있어요. 고르면 계산에 반영해요." 안내. 선택 칸: '선택 안 함'(기본) + 자치구 25개(⑧ `/regions/districts`, `lib/masters.js`의 `loadDistricts`). ②에 `residence_district_code`로 보내고(선택 안 함이면 null) 지원사업 거주 조건 판정에만 쓰인다 — 점수 · 순위와는 무관. `ts-cond`의 `residence`에 저장되고, 값이 없던 예전 `ts-cond`는 '선택 안 함'. 골랐으면 2단계 '입력한 조건'에 "○○구 거주" 칩 |
| 빈 칸 안내 | 계산을 막는 빈 항목(나이·자본금·면적·업종)이 있으면 주황 점 + "업종을 채우면 계산할 수 있어요"처럼 이유(문구는 `Recommend`가 만든다). 데스크톱은 하단 바 왼쪽, 모바일은 카드 맨 아래(`.s1-foot`). 다 채우면 사라지고 버튼은 색만 바뀐다(움직이지 않음) |

입력 칸은 포커스 시 파란 테두리와 링이 생기고 라벨도 파랗게 바뀝니다(오류 칸 제외). 기본 정보 칸은 모바일 · 데스크톱 모두 높이 52px입니다. 데스크톱은 업종 칩(대분류 50px)·제목을 키웁니다.

**숫자 애니메이션**(`NumInput`): 나이 · 경력 · 자본금 · 면적 칸은 입력 글자를 투명하게 두고 같은 자리에 숫자를 겹쳐 그립니다. 숫자가 바뀌면 바뀐 자리만 굴러 들어오는데, 값이 커지면 아래에서, 작아지면 위에서 들어옵니다(.32s). 경력 −/+도 같습니다. 처음 그릴 때와 지울 때는 움직이지 않습니다.

**움직임**(대시보드와 같은 결, `Recommend.css`의 '움직임' 묶음): 버튼은 hover 때 1px 떠오르고 화살표가 밀리며(이전 버튼은 왼쪽), 칩은 살짝 뜨고 누르면 작아집니다. 입력 칸 · 태그 상자는 hover 때 테두리가 진해지고, 태그 ×와 자격증 추천 줄은 바탕이 깔립니다. 2단계 목록 행은 바탕 + ▾가 살짝 내려가고, 지도 구는 옅어지고, 공고 원문 링크는 ↗ 방향으로 밀립니다. 3단계 목록 행은 hover 때 바탕이 깔리고 누르면 살짝 작아집니다. 동작 줄이기 설정이면 멈춥니다.

## 2단계 · 자치구별 예산 확인 (`Step2Gu`)

**용어**: 가용 예산 = 자본금 + 지원금. 추정 초기 임대비용 = 보증금(월세 15개월) + 월세 3개월 = 월세 × 18 (희망 면적 비례). 예산 여유 = 가용 예산 − 추정 초기 임대비용.

| 요소 | 내용 |
|---|---|
| 나이 안내 (`.s2-warn`) | 39세 초과면 노란 배너 |
| 요약 띠 (`.s2-summary`) | 얇은 띠. "25개 구 중 **N곳**에서 임대료를 감당할 수 있어요"(한 줄, 17~20px) 옆에 상태별 개수, 아래 25칸 상태 막대(높이 8px · 초록 통과 / 진회색 정보 없음 / 빨강 오류 / 연회색 탈락), 리스트 ↔ 지도 토글(작은 크기). 1040px 이상은 한 줄(결과 \| 토글), 그보다 좁으면 위아래로 쌓음. 입력한 조건 칩 6개(`condChips`)는 데스크톱에서 하단 바 왼쪽, 모바일만 요약 띠 안. 감당할 수 있는 구가 없으면 결과 아래 빨간 안내 |
| 이전 / N개 구에서 동네 추천받기 | 하단 바(`.rec-bar`) 오른쪽 끝에 [이전] + 다음 버튼. [이전]은 데스크톱만(모바일은 상단 바 ‹) |

**레이아웃** — 1040px 이상(`WIDE`)은 왼쪽 목록(또는 지도) + 오른쪽 고정 패널(고른 구의 계산서). 행을 누르면 펼치지 않고 패널이 바뀝니다(고른 행은 파란 바탕 + 왼쪽 띠). 그보다 좁으면 행을 눌러 아래로 펼칩니다.

**리스트 보기** — 서버 순서(가용 예산 큰 순). 목록 카드 머리에 제목 · 계산식 · 막대 범례(자본금 · 지원금 · 추정 초기 임대비용).

| 요소 | 내용 |
|---|---|
| 행 | 구 이름, 가용 예산, 예산 여유(통과 초록 / 탈락 빨강 / 임대료 정보 없음이면 "정보 없음" + 배지), ▾(펼치는 화면만). 목록 카드가 720px 이상이면 한 줄 표(이름 \| 막대 \| 금액)로 막대를 같은 세로줄에 세우고 예산 여유를 색 배경 배지로 |
| 예산 막대 | 자본금(파랑) + 지원금(초록) 누적, 검은 눈금 = 추정 초기 임대비용 |
| 탈락 | 반투명 + "탈락 · 추정 초기 임대비용이 가용 예산보다 N만 원 많아요" |
| 지원 사업 없음 (은평구) | "매칭된 지원 사업이 없어 자본금만으로 계산했어요" |
| 다른 지원 | 예산에 넣지 않은 지원의 유형별 개수 |
| 데이터 오류 (용산구) | 빨간 안내 상자 + [다시 계산], 고르거나 펼칠 수 없음 |

**계산서** (`GuDetail` — 넓은 화면 패널 · 펼침 · 모바일 지도 카드 공용). 처음엔 목록 맨 위(가용 예산 1위, 데이터 오류 구는 건너뜀).

| 요소 | 내용 |
|---|---|
| 머리 (패널 · 지도 카드) | 구 이름, 상태 배지(통과 / 탈락 / 임대료 정보 없음 / 데이터 오류), 큰 예산 막대 |
| 계산서 | 자본금 + 지원금 = 가용 예산, − 추정 초기 임대비용 = **예산 여유**(통과 초록 / 탈락 빨강, 22px). 왼쪽 표시는 막대 색과 같다 |
| 지원 사업 | 받을 수 있는 지원 사업(이름·금액, 이름을 누르면 줄 아래에 ③ 공고 상세), 중복 수혜로 제외(취소선 + 사유), 그 밖의 지원(유형은 흐린 글자 · 공고 링크). 묶음 제목 옆에 개수. **공고마다 한 줄**(줄바꿈 없음, 금액 · 공고 링크는 오른쪽 끝에 늘 보임). 이름이 길어 넘치면 `Slide`가 천천히 왼쪽으로 흘렸다가 되돌림(넘치는 만큼만 · 길수록 오래, 마우스를 올리면 멈춤, 동작 줄이기면 말줄임) |
| 꼬리 | 추정 초기 임대비용 기준(보증금 + 월세 3개월 · 면적 · 월세 · 권리금 등 제외) |

**지도 보기** — `GuVectorMap`. 넓은 화면은 지도가 화면 높이에 맞춰 커지고 계산서는 오른쪽 패널에, 좁으면 지도 아래 카드에.

| 요소 | 내용 |
|---|---|
| 구 색 | 예산 여유가 클수록 진한 초록, 탈락 회색, 정보 없음 빗금, 오류 연빨강. 선택한 구는 파란 외곽선 |
| 조작 | 구를 누르거나 Tab + Enter로 선택, 마우스를 올리면 툴팁 |
| 범례 | 지도 왼쪽 아래 |

## 3단계 · 추천 행정동 (`Step3Dong`)

진입하면 결과를 `last`에 저장합니다(대시보드·상세·비교에서 사용).

| 요소 | 내용 |
|---|---|
| 제목 | "추천 행정동 N곳" · "감당 가능한 N개 구 안에서 · 업종" |
| 하단 바 | 왼쪽 입력한 조건 칩, 오른쪽 [초기화] · [이전] + **[○○동 상세 분석 보기 →]**(고른 동의 상세, 이름이 길면 말줄임). 2단계에서 넘어와도 바 · 조건 · [이전]은 그대로 남는다. 모바일은 탭바 위에 [○○동 상세 분석 보기 →]만(1 · 2단계와 같은 자리) — 카드를 눌러 고르고 처음엔 1위. 추천할 동이 없으면 모바일은 바를 숨긴다 |
| 리스트 ↔ 지도 토글 | |
| 정렬 칩 | 종합점수순 · 영업 유지순(3년 영업 유지 확률, 없으면 뒤로) · 매출순 · 성장세순 (가로 스크롤) |

**화면 한 장에 맞춤(데스크톱, 화면 높이와 상관없이 — 아주 낮으면 640px 아래로는 줄이지 않음)** — 페이지는 스크롤하지 않습니다. 제목 · 정렬 칩 · 보기 전환을 한 줄로 모으고(칩이 넘치면 가로 스크롤), 그 아래 남은 높이를 왼쪽 동 목록과 오른쪽 상세 패널(지도 보기는 지도와 순위 목록)이 씁니다. **왼쪽 목록만 안에서 스크롤**하고, 오른쪽 상세 패널은 스크롤 없이 한 번에 보입니다. 바닥글은 숨기고 아래는 하단 바(80px) 자리를 비웁니다. 고른 동이 목록에서 안 보이면(상세에서 돌아왔을 때 · 정렬을 바꿨을 때) 목록 상자만 그 행까지 내려갑니다. 상세 패널은 왼쪽 동 목록 패널과 같은 높이로 늘어나되 내용은 본래 크기로 위에 두고, 안내 문구만 패널 바닥에 붙입니다. 그래도 넘치면 패널 안에서만 스크롤(안전장치).

**리스트 · 데스크톱** — 왼쪽 동 목록 패널(흰 카드 하나, 폭 320~400px, 안에서 스크롤 — 지도 보기의 순위 목록과 같은 모양. 행은 hover 때 바탕, 고른 행은 파란 테두리) + 오른쪽 상세 패널. 목록 패널은 스크롤바를 숨기고, 아래에 동이 더 있으면 아래 가장자리를 흰색으로 흐리게 + ⌄ 표시(맨 아래까지 내리면 사라짐). 처음 3단계에 왔을 때 한 번만 목록이 32px 올라갔다 내려오고 ⌄가 두 번 통통 튀어 더 있음을 알린다 — 본 기록은 `localStorage`의 `ts-seen-s3-hint`(값 `'1'`)에 남겨 새로고침 · 다음 방문에도 다시 하지 않음(저장소를 못 쓰면 그 화면에서 한 번). 상세 패널은 **세로 흐름** — 머리(이름 · 점수 · ♡) → 핵심 지표 4칸(패널 760px 이상이면 한 줄, 좁으면 2×2) → 왜 추천됐나요?(가로 전체, 패널 760px 이상이면 요인 줄을 한 줄로: 이름 \| 막대(10px) \| 점수 \| 원값 · 서울 상위 %) → 안내(바닥). 화면 높이가 840px보다 낮으면 세로로는 다 안 들어가 촘촘한 두 칸(패널 640px 이상일 때: 위 머리, 아래 왼쪽 지표 2×2 \| 오른쪽 왜 추천됐나요?, 맨 아래 안내)으로 바뀌고 간격 · 동 이름(24px) · 점수(36px)를 줄입니다.

| 요소 | 내용 |
|---|---|
| 목록 행 | 순위 배지(1~3위 파랑, 고른 행은 채움), 이름·구·주거지역 배지, 영업 유지(3년 확률 또는 점포 수 증감) / 월매출 80% 범위, 예산 여유, 점수(구간별 색), ♡. 누르면 선택(파란 테두리) |
| 상세 패널 | 이름·구·업종, 종합점수(44px), ♡ / **핵심 지표 4칸**(같은 크기의 회색 칸, 패널이 760px 이상이면 한 줄 · 좁으면 2칸씩): 영업 유지 칸(3년 영업 유지 확률 + 1년, 없으면 점포 수 증감 — 막대 없음) · 예상 월매출(중앙값 + 80% 범위 막대, 하한·상한 라벨) · 성장세(증감 색 + 신뢰도 낮음) · 예산 여유. 점포 수 증감이면 칸 아래에 안내 문구 / **왜 추천됐나요?**: 가중치, 요인 누적 막대, 요인별(매출·영업 유지·성장세) 기여 점수·막대·원값·서울 상위 %, 결측 지표(성장세 · 영업 유지)가 있으면 노란 안내 / 안내 문구([상세 분석 보기]는 하단 바에) |

**리스트 · 모바일** — 카드. 헤더(순위·이름·점수·♡), 영업 유지 칸 · 매출 범위 막대, 예산 여유 줄, "왜 추천됐나요? ▾"를 누르면 요인별 점수가 펼쳐집니다. 카드를 누르면(펼칠 때도) 그 동이 골라져 파란 테두리가 생기고 하단 바 버튼이 그 동을 가리킵니다.

**지도 보기** — `DongLeafletMap` + 순위 미니 목록(스크롤) + 선택한 동 요약 카드(범위 3칸, [상세 분석 보기 ›]는 모바일만 — 데스크톱은 하단 바). 핀이나 목록을 누르면 선택이 바뀌고 지도가 그 동으로 이동합니다. 1040px 이상은 지도를 넓게(3:2) · 화면 높이에 맞춰 키우고, 순위 목록이 지도 높이만큼 늘어납니다.

점수 색: 브랜드 파랑 한 가지의 진하기 — 80 이상 가장 진하게, 70 이상 · 60 이상 차례로 옅게, 그 아래는 회색(모두 흰 바탕 글자 대비 4.5:1 이상). 요인 색(왜 추천됐나요?): 매출 브랜드 파랑 · 영업 유지 민트 · 성장세 코랄(누적 막대에서 이웃해도 색약 시뮬레이션으로 구분되는지 검증, 이웃 요인 사이 2px 흰 틈, 요인 이름은 늘 글자로 함께).

## 반응형

| 폭 | 레이아웃 |
|---|---|
| 1040px 이상 | 1단계는 왼쪽 기본 정보 · 자격증 \| 오른쪽 희망 업종. 2단계는 화면 한 장에 맞춤(페이지 스크롤 없음, 바닥글 숨김) — 왼쪽 열(요약 띠 + 목록/지도, 목록은 머리 고정 · 안에서 스크롤, 지도는 남는 높이를 채움) + 오른쪽 계산서 패널(요약 띠 높이부터 바닥까지, 안에서 스크롤). 둘 다 스크롤바를 숨기고 3단계 동 목록처럼 아래에 더 있으면 가장자리 흐림 + ⌄, 처음 한 번만 목록이 살짝 올라갔다 내려옴(본 기록 `localStorage` `ts-seen-s2-hint`). 화면 높이 640px 미만만 페이지가 조금 스크롤. 3단계 상세 패널 고정(sticky) |
| 900~1039px | 1단계는 세 묶음을 위아래로 쌓음(데스크톱 크기). 2단계는 요약 띠 아래 목록, 행을 눌러 펼침 |
| 900px 미만 | 한 열(1단계 세 묶음도 위아래로), 다음 단계 바는 탭바 위, 3단계 리스트는 카드형 |

## 예외

- 추천할 동이 없으면(통과한 구에 예측 가능한 동이 없음) 3단계에 빈 상태와 [이전 단계로]를 보여 줍니다.
- `?step=3`으로 바로 들어와도 저장된 조건으로 계산합니다.
- 다른 화면에 다녀와 `step` 없이(메뉴 '추천받기') 들어오면 보던 단계 · 결과를 그대로 엽니다(메모리에만 기억, 새로고침하면 사라짐). 대시보드 '새 조건으로 계산'은 `?step=1`.
- [초기화](2 · 3단계, 데스크톱은 하단 바 [이전] 왼쪽 · 모바일은 상단 바 오른쪽 — 왼쪽 ‹와 짝): 입력을 기본값으로 · 결과를 비우고 1단계로. 대시보드 최근 추천 기록(`ts-last`)은 지우지 않습니다. 확인 창 대신 토스트 "입력과 결과를 초기화했어요 [되돌리기]"(6초)로 직전 상태(단계 · 고른 동 · 결과 · 입력)를 되살립니다.
