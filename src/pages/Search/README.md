# 직접찾기 (`/search?q=검색어`)

지도에서 행정동을 직접 고르거나 검색해 업종별 점수와 요약을 봅니다(명세 10.4).

- 파일: `Search.jsx`, `Search.css`
- API: ⑩ 업종(`lib/masters`), ⑱ 업종별 랭킹(지도 색칠 · 상위 목록), ⑦ 자동완성, ⑧ 자치구 · ⑨ 행정동(대안 경로), ⑫ 선택 동 카드
- 상태(로컬): `query`, `sugs`(⑦ 결과), `picked`(선택한 동: dong_code · 이름 · 구 · geo_code), `industryCode`, `browse`(구에서 고르기), `sheetOpen`(모바일 시트), `more`
- 지도: `DongLeafletMap`(지연 로딩) — 동 경계를 ⑱ total_score 5단계로 색칠, 상위 10곳 + 선택 동에 핀. 경계와는 geo_code로 잇는다

## 요소

| 요소 | 내용 |
|---|---|
| 검색창 | 공백을 뺀 1자 이상이면 200ms 뒤 ⑦(최대 8건). 일치 부분 굵게 + 구 이름(이름이 같은 동 구분). ↑↓ · Enter, × 지우기. 일치 없음 → "‘검색어’와 일치하는 서울 행정동이 없어요" |
| 업종 칩 | ⑩ 대분류 → 세부 업종. 기본은 ts-cond의 업종, 없으면 첫 업종. 바꾸면 ⑱ · ⑫를 다시 부른다 |
| 상위 목록 | ⑱ 앞 5곳(10위까지 보기 / 접기): 순위 · 동명 · 구명 · 성장세 · 점수. "구에서 고르기 ›" → ⑧ 자치구 칩 → ⑨ 행정동 목록 |
| 지도 | 동 클릭 · 핀 클릭 → 선택, 구 클릭 → 그 구의 ⑨ 목록 |
| 선택 동 카드 | ⑫ 종합점수 · 예상 생존 · 예상 월매출(중앙값 + 80% 범위) · 성장세 · 점포 수준(적음/보통/많음 · 점포 N곳) · ♡ · [상세 분석 보기 ›] → `/dong/{dong_code}?industry_code=&from=search` |

## 예외

- 점포 데이터 없음(⑫ store_count_latest null) → "○○ 데이터가 없어요" + 가까운 동네 2곳(경계 중심점 거리, ⑱에 점수가 있는 곳, 구 제한 없음).
- 예측 불가 → 카드의 생존 · 매출에 "예측 불가".
- geo_code가 없는 동(위례동 등 2013년 이후 신설) → 지도에 그리지 않고 목록 · 카드에 "지도에 표시되지 않음".
- ⑱ · ⑫ · ⑧ · ⑨ 실패 → 영역별 "다시 시도".
